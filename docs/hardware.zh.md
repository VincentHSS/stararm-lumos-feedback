## 连接诊断

SDK 导入优先使用配置绑定的 `interface_py` 构建目录，并仍严格核对包装器、扩展及
实际加载的原生库。CMake 安装会改写扩展 RUNPATH，安装副本因此可能与构建文件
哈希不同；本版直接加载已绑定的构建，不放宽哈希。若旧进程已加载不同构建，需退出
并重新启动，不能在运行中替换原生模块。

0.5.1 会在中英文页面区分接口不存在、未启动、波特率不符、总线故障、系统查询失败、
缺少 `ip` 命令和查询超时。可用 `lsusb` 与 `ip -details link show can0` 做只读检查。
若没有识别到 USB-CAN 或 `can0`，先重新插接 USB 数据线、尝试其他 USB 口，待系统
识别后再点击连接。若接口已出现但未启动，按本机接线与配置设置 1000000 bit/s。
页面不会自动修改网络接口、重置 USB 或绕过检查。Leader 串口也是独立的 USB 设备；
页面的 CAN 查询成功不代表 Leader 串口已连通。

## 在同一页面启动跟随与监测

网页提供“基础跟随”“跟随并监测”和“力反馈”入口。先停止当前只读采集，再选择
所需模式；一次只允许一个采集或控制会话，前一会话清理完成后才能重新启动。
基础跟随会使能 Lumos 并发送运动目标。跟随并监测还计算模型、残差、预计阻尼与
内存静止统计，两个模式都不写 Leader 阻尼；新款原生 HD 板仍可独立保持／释放 Leader。
力反馈仅对已审核的配置开放；当前
工程配置仍显示不可启动及具体原因，不能从网页修改质量覆盖或授权标记。

运动启动先验证配置、绑定与 SDK 来源，初始化 Leader 查询和 CAN 监听，随后在
构造 Lumos SDK 前，用真实新帧核对 Follower、Leader 映射目标与配对起始姿态及限位。
门槛复用本机启动容差，夹爪首目标仍锚定真实当前开度。不匹配会保留具体关节偏差，
不使能 Lumos、不自动移动到起点、不改校准。这仍是默认 home 策略；下方命令行示例
沿用它。

### 工程 follow/monitor 显式按当前姿态对齐

在页面明确选择“按当前姿态对齐”（`current_aligned`）。该选项仅供工程
`follow/monitor`，不授权力输出。默认仍为 home 对齐，继续使用原配对校准、坐标映射、
方向和限位。

1. 让 Follower 在稳定支撑上落稳，作为本次起始姿态，无需将 J4 托回校准 home。
   同时确认该姿态及周围工作空间允许计划中的跟随动作。
2. 按页面用原校准逆算出的当前目标，对齐 Leader ID 0–5。这些值是舵机角度，
   不是 Follower 关节角度。启动前关闭 TypeLJ 夹爪。
3. 停止只读采集，选择基础跟随或跟随并监测。有新款按钮板时，等检测提示出现后
   再按 HD；全部启动检查期间均保留 Follower 的稳定支撑。

SDK 构造前，当前姿态预检要求至少连续 0.5 秒真实新帧稳定，逐轴主从误差不超过
2°、目标单步限制或原启动容差中的最小值，满足原限位、SDK J2 ≥ −1.57 rad，以及 Follower
归一化夹爪开度 ≤ 0.01。缓存、重复或过期数据不能证明稳定。本次启动参考仅在
内存中使用，不改写配对 home。

SDK 构造后，取得新 CAN 状态，复核相对已接受姿态的漂移及 SDK 状态一致性，
然后才发送固定 raw 姿态和零目标速度。继续检查 2 秒稳定后，再进入原限速与单步
限幅的正常跟随。检查失败会停止，不采用变化后的姿态或扩大容差。

SDK 在构造内部已经使能电机并启动自身控制循环，早于本程序发送固定目标，
整个过程不是原子保持。仍需稳定支撑，检查完成不代表松开支撑后 J4 一定能保住。
该启动流程尚未经真机验证；须按实际装配核对模型覆盖，正式力输出仍需实测响应及
原生按钮仲裁验收。[SDK 启动审查](sdk-startup-review.md)记录固定源码与二进制证据。

### 工程 follow/monitor 显式当前位置相对起步

0.6.6 新增页面显式选择“当前位置相对起步”（`current_relative`），仅供工程
`follow/monitor`。默认仍为 home，`current_aligned` 继续保留。Follower 姿态可能通过
自身检查，但逆算的 Leader 目标超出配对校准范围；绝对当前姿态对齐会拒绝该目标。
相对模式不改原校准，也不要求 Leader 到达不可达的绝对目标。

1. 让 Follower 在稳定支撑上落稳、关闭 TypeLJ，并核对工作空间。把 Leader 放在
   校准范围内稳定、可操作的位置。页面中的 Leader home 是校准参考，相对起步
   不要求到达该参考或逆算的绝对目标。
2. 显式选择相对方式，停止只读采集，再启动基础跟随或跟随并监测。有新款按钮板时，
   仍等检测提示出现后再按 HD。捕获期间保持两端稳定，Follower 全部启动过程中
   保留支撑。
3. 预检核对 Follower 稳定反馈并查询 Leader 原始起点；六个臂部关节分别固定本次偏移：`Follower 实际 SDK
   位置 − Leader 原映射目标`。随后目标为 `原映射目标 + 本次固定偏移`，整个会话
   不随漂移重新计算偏移。

原方向、增益、ID、限位、速度和单步限制全部保留。夹爪不加相对偏移，沿用原开度
映射及目标限速。Follower 七轴需至少连续 0.5 秒真实新帧稳定。Leader 起点由查询取得，SDK
构造后再次查询并按同一固定偏移核对。上述当前姿态的全部准入与启动检查继续生效，包括按偏移后的目标核对逐轴误差不超过 `min(2°，目标单步限制，原启动容差)`、
原限位、SDK J2 ≥ −1.57 rad、Follower 夹爪闭合、构造后新 CAN/SDK 一致性及漂移
检查、固定 raw 目标及零目标速度，以及正常跟随前的 2 秒稳定检查。本次偏移在清理时
清除，不写校准、设置、日志或历史文件。

SDK 仍在构造内先使能，随后才能发送固定目标；该选项不提供原子保持，也不证明
松开支撑后 J4 会保住。实际相对起步及跟随尚未经真机验证；须按实际装配核对模型
覆盖，正式力反馈仍需实测响应及原生 HD 仲裁验收。

“停止并退出控制”会阻断后续新目标、释放本程序管理的 Leader 输出并退出 SDK；
已进入 SDK 的调用不能撤回。退出后可能失去重力支撑，先支撑从臂。此按钮不是
机械急停，也不保证机械保持；故障不自动重连或继续运动。网页持久保存当前功率上限及
上述本机按钮板选择，当前姿态启动参考只留在内存。

若 SDK 清理失败，页面明确报告电机状态未确认，并禁止本页再次启动任何运动模式；
只读诊断仍可使用。先支撑从臂并排查实际状态，不以页面停止状态推断电机已经失能。

## 命令行分阶段接机

先退出上述查询服务。两臂按本次配对校准回到相应起始姿态，停止其他使用相同 CAN/
串口的控制程序。已有 companion 的网页端口与本程序不同也可能使用同一 CAN；
本程序的资源锁只能排除遵守相同锁的程序。

```bash
# 下面两项会构造 SDK、使能电机并实际跟随；软件不写 Leader 力输出，新板可独立动作。
bash scripts/run_feedback.sh follow --seconds 15
bash scripts/run_feedback.sh monitor --seconds 30
```

`follow` 保留逐帧加速度、速度、限位、温度、故障及通信检查。
`monitor` 额外计算整臂模型、残差、预计阻尼和内存静止统计。
遇到异常即停止；不要扩大保护阈值或修改哈希绕过检查。
完成基础跟随、质量覆盖及多姿态空载/带载调参后，建立单独审核的
`configs/feedback.reviewed.local.json` 和匹配绑定，再使用 `run`。
工程观测配置不会被自动改为力反馈配置。
即使配置已审核，检测到新款原生 HD 板仍会额外禁止 `run`。

## 绑定 TypeLJ 闭合端观测

确认夹爪实物完全闭合，并已观察到稳定、真实新到达的原始电机帧后，可以在工程
`version: 3` 配置中记录：

`gripper_closed_observation` 仅包含 `operator_confirmed_closed: true` 和
`raw_position_code` 两个字段。后者必须填写实际夹爪完全闭合时观测到的 16 位整数；
源码发布不提供实测闭合码或可直接使用的观测配置。

只有在确认夹爪实物完全闭合、且读到稳定真实新帧后才可记录。嵌套字段必须完整，
确认值须为 `true`，原始码须为 16 位整数，按第七轴 `p_max` 解码。闭合参考值须大于
零且最多为 16 个位置 LSB，这是软件调试约束，不是厂家精度说明。闭合端上界为该
观测参考加原有电机位置余量，张开端下界保持原样。
这个字段不改全域偏移、SDK 命令、坐标转换或原配对校准；配置及观测变化后须正常
重新生成绑定。仅工程 inspect/follow/monitor 接受该字段，正式力反馈配置拒绝使用。
这只记录保护参考，不代表基础跟随、阻尼或完整实物行程已经验证。
